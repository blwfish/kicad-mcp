# kicad-mcp Code Review — Final Report

## Executive Summary

A multi-agent adversarial review of the kicad-mcp codebase (~25K LOC source, ~18K LOC tests) surfaced **44 confirmed findings**, plus 57 low/nit items passed through without full verification, and 2 findings rejected as false positives.

**Confirmed findings by severity** (using the verifier's adjusted severities):

| Severity | Count |
|----------|-------|
| Critical | 0 |
| High | 12 |
| Medium | 18 |
| Low / Minor | 71 (14 verified-then-downgraded + 57 passed-through) |

After verifier severity adjustments, several findings originally filed as Medium/High were downgraded to Low because their trigger conditions are unreachable in practice (e.g. fallback chains that prevent the divergent branch) or their impact is purely cosmetic. The report below presents the **30 confirmed High/Medium findings** in full, then condenses the Low/Minor tail.

### Recurring Themes

The single most valuable output of this review is the pattern structure across findings. Six themes dominate:

**1. Rule-3 single-source-of-truth violations — duplicated logic that has already drifted.** This is the most pervasive and dangerous class, and it is exactly the family that previously shipped the KiCad-10 dead-board bug. Confirmed instances: two divergent footprint-nudge implementations where one can push parts off-board ([H](#h-autoroute-nudge)); `_strip_pin_suffix` duplicated between parse.py and intent.py ([M](#m-strip-pin-suffix)); the audit summary re-implementing silkscreen AABB with strict `<` while the canonical helper uses non-strict ([M](#m-aabb-strict)); `footprint_overlaps` reporting max-axis gap while the violation gate uses min-axis ([M](#m-gap-minmax)); the regulator-classification regex table encoded in three drifted places ([L](#l-regulator-regex)); the op-amp regex duplicated and drifted between `identify_amplifiers` and `identify_filters` ([M](#m-opamp-regex)); pad-clearance threshold logic re-inlined instead of calling `clearance_violation` ([L](#l-pad-rule3)). The lesson is consistent: when a semantic distinction is encoded in two syntactic sites, the two *will* drift, and a comment guard is not enforcement.

**2. Massive dead code that duplicates live logic.** The entire `register_schematic_tools()` function (~1,277 lines, ~30 `@mcp.tool()` defs) is unreachable and re-implements every operation the live router already handles — and the two copies have already drifted in type annotations and a resurrected `clone_schematic` ([H](#h-dead-schematic), corroborated by 2 reviewers). This is both a maintenance hazard and a confusion source: a maintainer editing a module-level helper can silently diverge from its dead twin.

**3. Silent data loss at external-data ingestion boundaries (CLAUDE.md data-capture rule).** Multiple parsers drop data with no counter, flag, or stated reason. The most severe: the DRC parser silently discards `unconnected_items` and `schematic_parity` arrays, so a board with 12 unrouted nets reports a clean bill of health ([H](#h-drc-arrays)). Also: pad-assignment failure produces an electrically-dead board while returning `status:ok` ([H](#h-pad-deadboard)); LCSC shard ingestion drops malformed rows with no counter ([M](#m-lcsc-shard)); JSON BOM with an unrecognized container shape vanishes silently ([M](#m-json-bom)); LCSC search truncates with no flag while its sibling router has one ([M](#m-lcsc-truncate)); `ResolvedPart.attributes` is always `{}` ([M](#m-resolved-attrs)).

**4. Syntactic-semantic seam bugs — a single character or substring carrying a semantic distinction.** `resolve_mcu` mis-resolves ESP32-C3/C6/S2 to the classic WROOM-32E via a bare `esp32` substring ([H](#h-resolve-mcu)); `is_power_net` classifies `-RESET`/`-CS` as power rails via bare `+`/`-` prefixes ([M](#m-power-net)); GAIN/ADC/DAC role tokens promote config macros to false pins ([M](#m-gain-roles)); the `MAX\d+` and `RM\d+` sensor regexes catch unrelated Maxim/trimmer parts ([M](#m-max-regex), [L](#l-rm-regex)).

**5. Threshold and falsy-collapse bugs (CLAUDE.md threshold rule).** GPIO 0 is a valid pin but `signals.get(A) or signals.get(B)` discards it, dropping whole bus subcircuits ([M](#m-gpio-zero)); `edit_label` unconditionally clobbers rotation/size on every edit ([H](#h-edit-label)); `estimate_board_size` applies padding 2x–4x depending on which dimension dominates ([M](#m-board-padding)); the 'extended' assembly tier means "any" to the SQL filter but "penalize basic" to the scorer ([M](#m-extended-tier)).

**6. Tautological / mock-asserting tests that cannot fail.** A cluster of "boundary" and "truncation" tests assert on values they configured on the mock, with the real logic living in a mocked-away subprocess. The pad-clearance truncation test ([H](#h-test-truncation)) and threshold tests ([H](#h-test-threshold)) provide false confidence; the highest-traffic external parser (kicad-cli netlist XML) has zero field-survival coverage in the default suite ([H](#h-test-netlist)). Several non-determinism and persistence bugs (`hash()` for filenames defeating DRC history across restarts, [H](#h-drc-hash)) would have been caught by a single real test.

## High Severity

### Firmware

<a id="h-resolve-mcu"></a>
**`resolve_mcu` silently mis-resolves ESP32-C3/C6/S2 to the classic WROOM-32E.** *High · correctness ·* `src/kicad_mcp/utils/firmware/knowledge.py:185-207`
The WROOM-32E card lists `board_match: ["esp32dev", "esp32"]`; the bare `esp32` substring matches any C3/C6/S2 board id with no dedicated card, resolving to a different chip with a different pinout and USB capability instead of producing the documented `mcu_unknown` gap. This contradicts the module's stated honesty contract and `parse.idf_target_defines`, which correctly selects the C3/C6/S2 preprocessor branch — so the active pin block and the resolved symbol disagree.
**Fix:** require the resolved card's implied IDF target to agree with `idf_target_defines(board_id)`, or drop bare `esp32` and exclude `-c3`/`-c6`/`-s2` tokens. Producing `mcu_unknown` is the correct honest behavior until those cards exist.

<a id="h-prefetch-corroboration"></a>
**`prefetch.synthesize_i2c_card` grades 'high' with no address corroboration.** *High · correctness ·* `src/kicad_mcp/utils/firmware/prefetch.py:77-102`
The high-confidence gate requires only SDA+SCL by name, supply, ground, single-unit, and no unexplained pins — *not* address-table corroboration. The production CLI always calls it with `address=None`, so any symbol with pins named SDA/SCL/VDD/GND grades 'high' regardless of identity. This is exactly the "pin named SCL isn't an I2C clock" trap SPEC §11/§12 forbids ("mass generation without this gate ships subtly-wrong cards at scale"), and it is inconsistent with the sibling `draft_card`, which correctly requires `corroborated` for high.
**Fix:** add `and corroborated` to the high gate; since the bulk CLI can't supply per-symbol addresses, downgrade all address-less syntheses to 'low' (forcing the spec's intended human review). Add a boundary test pinning a non-I2C SDA/SCL/VDD/GND part with `address=None` as 'low'.

### PCB Tools

<a id="h-pad-deadboard"></a>
**Pipeline silently builds an electrically-dead board when pad assignment fails.** *High · correctness ·* `src/kicad_mcp/tools/pcb_pipeline.py:346-397, 1112-1117`
Step 4's embedded script always prints `status:ok` regardless of how many pad assignments failed, and the pipeline never compares `pads_assigned` against the requested count. A run where every net lookup fails assigns 0 pads, returns ok, and proceeds to autoroute/zone-fill a dead board — the exact failure class that motivated the net-injection consolidation. The injection half got a guard; the pad-assignment half did not.
**Fix:** return the requested count from the step; if `pads_assigned == 0` while assignments were requested, fail the pipeline. On partial loss, promote a capped `assignment_errors` summary to a top-level warning.

<a id="h-autoroute-nudge"></a>
**Two divergent footprint-nudge implementations; the autoroute version can push parts off-board.** *High · architecture ·* `src/kicad_mcp/tools/pcb_autoroute.py:605-689` vs `src/kicad_mcp/tools/pcb_drc_fix.py:144-224`
The same "nudge overlapping footprints apart" operation is encoded twice and has drifted: the DRC-fix version checks board-outline containment before each move and refreshes bboxes after moving; the autoroute version computes `outline` but never uses it (dead variable) and nudges unconditionally against stale boxes, so it can shove a footprint past Edge.Cuts and re-nudge against pre-move geometry. Both call sites are live.
**Fix:** extract the nudge algorithm into one shared helper-string constant with containment + per-move bbox refresh, consumed by both embedded scripts. At minimum, make the autoroute version use the `outline` it already computes.

### Schematic Tools

<a id="h-dead-schematic"></a>
**Entire `register_schematic_tools()` (~1,277 lines) is dead code that duplicates the live router.** *High · architecture ·* `src/kicad_mcp/tools/schematic_impl.py:155-1431` *(corroborated by 2 reviewers)*
`server.py` registers only `register_schematic_router`; `register_schematic_tools` is referenced nowhere in src/ or tests/. Its body re-defines every module-level helper as an inner closure and re-implements ~30 tools that the live router already handles as operations — and the copies have drifted (type annotation `dict` vs `dict[int, list[str]]`; a `clone_schematic` that v0.10.0 documented as *removed* still lives here and is resurrected as router op `clone`).
**Fix:** delete `register_schematic_tools()` entirely (lines 155–EOF), keeping only the live module-level helpers (lines 42–154). Separately decide `clone`'s fate deliberately — if it was removed as broken, the router's `clone` op resurrects that bug.

<a id="h-edit-label"></a>
**Live `edit_label` unconditionally clobbers a label's rotation and size on every edit.** *High · correctness ·* `src/kicad_mcp/tools/schematic.py:828-829`
The router signature declares `rotation: float = 0.0` and `size: float = 1.27` as non-Optional defaults, and the edit branch *always* executes `label.rotation = rotation` / `label.size = size` regardless of whether the caller supplied them — so renaming a label's text silently resets its rotation to 0 and size to 1.27. The inline comment claims the opposite of what the code does; the dead impl version is actually correct (guards on `is not None`). `test_edit_text` renames a label but never asserts rotation/size are preserved.
**Fix:** guard the writes like the position write above them (`if rotation != 0.0: ...`), or give `edit_label` dedicated Optional params. Add a regression test asserting `edit_label(new_text=...)` leaves an existing rotation=90/size=2.54 untouched.

<a id="h-design-intent"></a>
**Malformed/edited intent YAML raises an uncaught exception instead of a structured error.** *High · correctness ·* `src/kicad_mcp/tools/design.py:173-205, 248-256`
`_op_expand`, `_op_generate`, and `_op_show` call `load_intent` with no try/except on an external file that may be hand-edited, truncated, or from a different schema version. `load_intent` → `from_dict(yaml.safe_load(...))` has no guards: malformed YAML, a non-dict top level, a missing required net key (`n["name"]`), or an unexpected key (`Peripheral(**p)`) all propagate to fastmcp as a raw traceback. This is internally inconsistent — `_op_import` carefully catches `SidecarError`/`OSError`.
**Fix:** wrap each `load_intent` call in try/except `(yaml.YAMLError, OSError, KeyError, TypeError, AttributeError)` returning `{status:error, code:"invalid_intent", ...}`; better, give `load_intent` its own `IntentError`.

### Utils

<a id="h-drc-arrays"></a>
**DRC parser drops `unconnected_items` and `schematic_parity` arrays from KiCad's JSON report.** *High · correctness ·* `src/kicad_mcp/tools/drc_impl/cli_drc.py:86-111`
kicad-cli emits three sibling top-level arrays; the parser reads only `violations`. A board with 0 clearance violations but 12 unrouted nets and 3 missing footprints reports `total_violations: 0, success: True` — a clean bill of health on a broken board. Verified live against KiCad on a real board (9 violations + 2 unconnected items; the 2 are silently dropped). This is a current-schema data-loss bug, distinct from the future-rename gap already pinned by `test_unknown_top_level_key`.
**Fix:** read all three arrays; either merge into the categorized count (tagged by source) or surface as `unconnected_count`/`parity_count` and include in `total_violations`. At minimum, count unrecognized array-valued keys into a `dropped_report_sections` field.

<a id="h-library-stale"></a>
**Symbol/footprint staleness check ignores user library dirs — user edits never trigger a rebuild.** *High · correctness ·* `src/kicad_mcp/utils/library_index.py:453-457, 590-666`
`rebuild_*` indexes both the system path and extra user dirs (from `KICAD_USER_LIB` and the user's lib-tables), but `symbols_stale()`/`footprints_stale()` pass only the single system path to `_is_stale`, which `os.scandir`s that path alone. Editing a symbol/footprint in a user library returns `stale=False` forever, so searches return stale results until the system library happens to change.
**Fix:** have `_is_stale` iterate the same `scan_dirs` the rebuild uses, and fold the set of extra dirs into the stored fingerprint. A single source of truth for "which dirs are indexed," shared by rebuild and staleness.

<a id="h-drc-hash"></a>
**DRC history filename uses non-deterministic `hash()` — history is lost on every process restart.** *High · correctness ·* `src/kicad_mcp/utils/drc_history.py:38-42`
`project_hash = hash(project_path) & 0xFFFFFFFF` uses CPython's per-process-randomized string hash, so the same project yields a different filename in every new process. After any MCP restart, `compare_with_previous()` returns `None` ("no history") even though entries exist on disk, and the directory accumulates orphaned files — defeating the module's entire purpose.
**Fix:** use a stable hash, e.g. `hashlib.sha1(project_path.encode()).hexdigest()[:8]`. Built-in `hash()` must never key anything that persists across processes.

### Tests

<a id="h-test-truncation"></a>
**`test_truncation` asserts on its own mock return — the `[:50]` cap lives in the mocked-away subprocess.** *High · test-quality ·* `tests/test_pad_clearances.py:209-226`
The test sets `mock_run.return_value = {... 'violations_truncated': True}` then asserts that exact value back. The real cap and the `> 50` boundary flag live inside the embedded pcbnew script string, never executed under the mock — so the test cannot fail even if the cap were `[:5]` or the boundary flipped to `>= 50`.
**Fix:** move truncation into a pure Python post-processor (`_truncate_violations(result)`) and boundary-test it at 49/50/51 violations.

<a id="h-test-threshold"></a>
**Pad-clearance threshold boundary (`gap < min_cl`) has no real test — every "boundary" test asserts on mock returns.** *High · test-quality ·* `tests/test_pad_clearances.py:82-95, 97-108, 130-226`
The strict-`<` violation gate, the `overlap = gap <= 0` flag, the signed-gap math, and the footprint-pair dedup are all unit-untested; every test mocks `run_pcbnew_script` and asserts its configured return. The embedded script also uses different key names (`x0/x1`) than the well-tested `GEOMETRY_HELPER`, and diverges from canonical `clearance_violation` at the touching/`min_cl==0` boundary. A regression flipping `<` to `<=` would pass the whole suite.
**Fix:** extract the pad-pair gap+threshold decision into a pure helper and boundary-test it (below/at/above `min_cl`, plus `gap==0` touching), following `test_geometry.py`.

<a id="h-test-netlist"></a>
**The kicad-cli netlist XML parser — the production data-capture path — has no field-survival test in the default suite.** *High · test-quality ·* `tests/test_netlist_tools.py:62-82`
`extract_netlist_via_cli` is the authoritative extractor for every component/net the system consumes, with a non-trivial field set (dnp bool coercion, datasheet, all `<field>`/`<property>` entries, per-node attributes, malformed-skip counters). The default tests mock the entire extractor and assert only the router envelope; the only real calls are skipped in the no-KiCad CI matrix. The parser could silently drop dnp, datasheet, or every property and CI would stay green.
**Fix:** feed a hand-crafted kicadxml string through the same ET path (no KiCad needed) and assert each field survives, including the `malformed_components_skipped`/`malformed_nets_skipped` counters and leading-`/` stripping.

## Medium Severity

### Firmware

<a id="m-gain-roles"></a>
**GAIN/ADC/DAC role tokens promote config-value macros to false pins.** *Medium · correctness ·* `src/kicad_mcp/utils/firmware/parse.py:94-96, 256-274`
`_GENERIC_ROLES` includes GAIN/ADC/DAC, which are far more commonly amplifier/codec config settings than pin names; the 0..48 value gate can't tell a gain-in-dB from a GPIO. `MAX_GAIN 12`, `AUDIO_GAIN 3`, `AUDIO_DAC 5` all classify as pins and generate spurious orphan nets (flagged, but real).
**Fix:** drop GAIN/ADC/DAC from the allow-list (the MAX98357A GAIN pin is template-owned), or require a `_PIN`/`_GPIO` suffix for these specifically ambiguous tokens. Add a boundary test pinning `MAX_GAIN`/`AUDIO_GAIN` as OTHER.

**Pin macros with `GPIO_NUM_x` or parenthesized/block-comment values are dropped with no user-visible gap.** *Medium · correctness ·* `src/kicad_mcp/utils/firmware/parse.py:143-161, 256-274`
`_as_int` rejects `GPIO_NUM_5` (a common ESP-IDF idiom), `(4)`, and `5 /* comment */` (block comments aren't stripped), downgrading a clearly-pin-named macro to OTHER. The `-1` sentinel gets a visible `invalid_pin` gap; a valid `GPIO_NUM_5` only lands in buried `provenance.unparsed` — worse treatment for the real pin.
**Fix:** in `_as_int`, strip `/* */`, unwrap parentheses, and resolve `GPIO_NUM_<n>`. At minimum surface a pin-specific gap when a pin-named macro fails value parsing.

<a id="m-strip-pin-suffix"></a>
**`_strip_pin_suffix` / `(_PIN,_GPIO)` duplicated between parse.py (declared single source of truth) and intent.py.** *Medium · architecture ·* `src/kicad_mcp/utils/firmware/parse.py:41, 164-168`
parse.py declares itself the source of truth for macro classification, yet intent.py re-defines an identical `_strip_pin_suffix` with the suffix tuple hardcoded inline. intent.py already imports from parse but not this helper; if the suffix set is extended, the two copies drift and intent.py's net-naming silently disagrees with parse.py's classification.
**Fix:** export `_strip_pin_suffix`/`_PIN_SUFFIXES` from parse.py; have intent.py import it and delete the duplicate.

<a id="m-gpio-zero"></a>
**Falsy-zero collapse drops bus subcircuits when a signal lands on GPIO 0.** *Medium · correctness ·* `src/kicad_mcp/utils/firmware/templates.py:317, 373-374, 438-439`
Five sites use `bus.signals.get(A) or bus.signals.get(B)`. GPIO 0 is a valid ESP32 pin (`GPIO_MIN == 0`) but is falsy, so a primary-role GPIO of 0 falls through to the alternate (or None). In `i2s_output_amps`, LRC on GPIO 0 with WS absent yields None → the entire stereo amp pair is silently skipped.
**Fix:** replace the `or` fallback with a None-aware helper (`_first(signals, *roles)`). Add a boundary test with a signal on GPIO 0.

**`from_dict` raises on any unknown field, contradicting its documented "silently drop fields" contract.** *Medium · correctness ·* `src/kicad_mcp/utils/firmware/intent.py:362-388`
The comment promises forward-compat ("a newer doc loaded by older code would silently drop fields"), but `Mcu(**mcu_d)`, `Peripheral(**p)`, `Bus(**b)`, `Gap(**g)`, `Endpoint(**e)` all raise `TypeError` on any unknown key. A v4 schema or a hand-edited intent YAML with a typo'd key crashes `load_intent`. The `Net(...)` branch uses explicit kwargs and is asymmetrically tolerant.
**Fix:** filter each dict to the dataclass's known fields (matching the documented contract), or change the docstring to state unknown fields are a hard error and raise a clear domain error.

### PCB Tools

<a id="m-gap-minmax"></a>
**`footprint_overlaps` reports the larger-axis gap while the violation flags on the smaller (binding) gap.** *Medium · correctness ·* `src/kicad_mcp/tools/pcb_keepout.py:293-296, 316`
The entry is gated by `clearance_violation` (which uses `min(gap_x, gap_y)`), but the reported `gap_mm` is computed inline as `max(gap_x, gap_y)`. For a pair separated on both axes, the warning can read "R1 and R2 are only 0.9 mm apart (min clearance: 0.5 mm)" — a value *larger* than the clearance it claims to violate. Also a Rule-3 duplication of `signed_gap_mm`.
**Fix:** replace the inline computation with `gap_mm = signed_gap_mm(a_box, b_box)` (already available via the injected helper).

<a id="m-aabb-strict"></a>
**`audit` summary re-implements silkscreen AABB with strict `<` while the canonical check is non-strict.** *Medium · architecture ·* `src/kicad_mcp/tools/pcb_keepout.py:1043-1044, 1051-1052, 1068-1069`
`_op_all_summary` defines its own `_aabb` with strict inequalities, while `_op_check_silkscreen_overlaps` uses the non-strict `aabb_overlap` (documented to match KiCad DRC's "touching counts as overlap"). The same board audited via `all` vs `check_silkscreen_overlaps` yields different overlap counts for any pair whose boxes touch exactly. The canonical helper is already injected into the script.
**Fix:** call `aabb_overlap(...)` instead of the local strict `_aabb`.

**`_op_add_zone` does not validate the layer name — a misspelled layer creates a zone on `UNDEFINED_LAYER (-1)` and still returns `status:ok`.** *Medium · correctness ·* `src/kicad_mcp/tools/pcb_zones.py:62`
`zone.SetLayer(board.GetLayerID(params["layer"]))` passes user input straight in; `GetLayerID` returns -1 for an unknown name, `SetLayer(-1)` doesn't raise, and the bad zone is saved with `status:ok`. The sibling `connect_pads` param two lines below *is* validated against an allow-list. The same unguarded pattern exists at `pcb_routing.py:43`.
**Fix:** guard `if layer_id < 0: return {"error": ...}` before `SetLayer`; consider a shared `validate_layer` helper for both files.

**Pipeline net injection writes external net names without the S-expression-escaping validation the single-net injector enforces.** *Medium · correctness ·* `src/kicad_mcp/tools/pcb_pipeline.py:295, 323-343`
`pcb_nets._op_add_net` rejects net names containing `"`, `\`, `\n`, `\r`; the pipeline passes net names straight from kicad-cli (ultimately user-authored labels) into `inject_net_definitions` with no such check. A label like `BUS"A` is written as `(net N "BUS"A")`, corrupting the .kicad_pcb. The two injectors share the writer but apply inconsistent input contracts. *(Filed as security; reclassified by verifier as data-integrity.)*
**Fix:** push escaping into `format_net_line` so every caller is safe by construction (preferred), or apply the same validation in the pipeline with a counter for skipped names.

**FreeRouter incomplete-count parser silently returns 0 on no-match, corrupting best-pass selection.** *Medium · correctness ·* `src/kicad_mcp/tools/pcb_autoroute.py:145-159, 416-419`
`_parse_freerouter_incomplete` returns 0 ("assume success") when neither regex matches; this feeds best-pass selection, so a pass whose output format isn't recognized scores as `incomplete==0` and wins over a pass that genuinely routed everything. A FreeRouter wording change makes the first pass win regardless of quality. (The final result is independently re-checked via SES import, but the per-pass ranking is not.)
**Fix:** return `None` on no-match, treat "unparsed" distinctly from "zero," prefer a parsed-0 pass over an unparsed one, and surface a `parse_failed` flag.

<a id="m-board-padding"></a>
**`estimate_board_size` applies padding twice / inconsistently depending on which dimension dominates.** *Medium · correctness ·* `src/kicad_mcp/tools/pcb_planning.py:113-124`
`min_dim` already includes `padding*2`; the per-aspect loop then adds `padding*2` again. When the component-fit floor dominates, padding is applied 4×; when the area dimension dominates, only 2×. The suggested board is silently oversized and its padding semantics differ by branch. (Conservative — too big, not too small.)
**Fix:** compute the bare floor `min_dim = max(max_width, max_height)`, take `max(area_dim, min_dim)`, then add `padding*2` exactly once. Add a boundary test where `min_dim` dominates.

### Schematic Tools

**Cache shard key derived from raw vs normalized `schematic_path` — `apply` can miss a state that `suggest` saved.** *Medium (adjusted down from High) · correctness ·* `src/kicad_mcp/tools/schematic_layout.py:197-204, 384-385`
`suggest` shards on the normalized path; `apply`'s fallback lookup uses the raw caller argument. A non-normalized but valid path (trailing slash, `./`, doubled slash) passed to both hashes to different shards, so `apply` returns `state_not_found`. *(Verifier downgraded: the `state_id` path is the primary happy path and fully bypasses this; the bug is latent for clean absolute paths.)*
**Fix:** normalize once at the tool boundary in `_op_apply` (mirroring `_op_suggest`), ideally pushing normalization into `cache._schematic_shard`.

### Utils

<a id="m-power-net"></a>
**`is_power_net` treats bare `-`/`+` prefix as power — misclassifies active-low/signed signal nets.** *Medium · correctness ·* `src/kicad_mcp/utils/netlist_parser.py:15-25, 33-39`
`_POWER_NET_PREFIXES` includes bare `+`/`-`, so `-RESET`, `-CS`, `-SIGNAL` classify as power rails. This propagates into 7 call sites: `topology.py` drops the net entirely from the signal graph; `pcb_pipeline.py` deprioritizes routing weight 10×; netlist analysis mislabels them. *(Requires bare-minus naming, common in EAGLE/Altium imports rather than KiCad-native `~{}`.)*
**Fix:** require a digit after the sign (e.g. `^[+-]\d`). Fix both the live function and the duplicated `POWER_NET_HELPER` together.

**Duplicated power-net classifier (`is_power_net` vs `POWER_NET_HELPER`) guarded only by a comment.** *Low (adjusted down from Medium) · architecture ·* `src/kicad_mcp/utils/netlist_parser.py:13-39`

<a id="m-extended-tier"></a>

### Cross-cutting

<a id="m-json-bom"></a>
**JSON BOM with neither 'components' nor 'parts' key is silently dropped with no error.** *Medium · correctness ·* `src/kicad_mcp/tools/bom.py:311-351`
A valid non-empty JSON BOM nesting rows under `bom`/`items`/`rows` (or keyed by refdes) leaves `components` empty and returns `([], ...)` with no error; `_op_analyze_bom` treats it as a benign skip. A populated-but-unrecognized BOM is indistinguishable from an empty one.

<a id="m-lcsc-truncate"></a>
**LCSC search silently truncates results with no truncated/overflow flag.** *Medium · correctness ·* `src/kicad_mcp/tools/lcsc.py:427-450`
`_op_search` returns results with no truncation signal; `search_components` hard-slices `results[:max_results]`. With the default `max_results=3`, a caller can't tell "only 3 matches" from "top 3 of 400." The sibling `library` router already returns `"truncated": len(results) == limit`.
**Fix:** expose the pre-slice candidate count and add `"truncated"`/`"total_candidates"`, matching the library router's contract.

<a id="m-resolved-attrs"></a>
**`ResolvedPart.attributes` is always `{}` — parametric attributes from the catalog/API are silently dropped.** *Medium · correctness ·* `src/kicad_mcp/tools/lcsc.py:124-143`
`_row_to_resolved` hardcodes `attributes={}` despite the dataclass advertising `attributes: dict[str, str]  # Parametric`. The upstream jlcparts attribute LUT is decoded for package/mfr/tier only; resistance/voltage/tolerance/etc. are dropped with no raw-store or stated reason, and the live-API path drops the rest too.
**Fix:** either carry a parametric dict through `search_components`/`get_component`/`_live_part_to_row`, or remove the field and document the exclusion so the API stops advertising a capability it never provides.

<a id="m-lcsc-shard"></a>
**LCSC/JLCPCB shard ingestion drops malformed rows with no error counter or bare-except narrowing.** *Medium · correctness ·* `src/kicad_mcp/utils/lcsc_db.py:418-468`
Three row-level failure classes (`except Exception` on `json.loads`, non-list row, `lcsc is None`) all `continue` with no counter; only successes are counted, and metadata records `total_components` but no dropped count. A schema-shifted shard can lose unbounded parts with zero signal. Shard-level skips log; row-level skips don't.
**Fix:** add per-reason drop counters, log per shard at WARNING when non-zero, write `rows_dropped` into metadata, and catch `json.JSONDecodeError` specifically.

**Peripheral-card validator crashes with KeyError instead of a clean CardError when a card omits 'bus'.** *Medium · correctness ·* `src/kicad_mcp/utils/firmware/cards.py:76-77, 123-140`
`validate_peripheral_card` reads `card["bus"]` at line 133, but `"bus"` isn't in `_PERIPHERAL_REQUIRED`, so a card omitting it skips the required-field loop and hits an unguarded subscript → `KeyError`. User-supplied cards under `KICAD_MCP_DEVICE_DIRS` crash `load_cards()` with an opaque traceback instead of the intended `CardError`.
**Fix:** add `"bus"` to `_PERIPHERAL_REQUIRED` (note `None` is a valid bus value, so the key must be present but may be null). Add a unit test pinning the missing-`bus` error.

## Methodology

This review used a multi-agent fan-out: ~14 review units each examined a subsystem (firmware front-end, PCB tools, schematic tools, utils, tests, and cross-cutting duplication/seam sweeps), and every finding was then passed to an independent adversarial verifier that re-read the cited code, confirmed or rejected the claim, and adjusted severity where warranted. Of the original set, **2 findings were rejected as false positives** and are not included here; **14 confirmed findings were downgraded** (mostly High/Medium → Low) when the verifier found the trigger condition unreachable in practice or the impact cosmetic. The 44 confirmed High/Medium/Low findings above each carry a verifier's confirmation; the 57 low/nit items were passed through without full re-verification and are presented as such. Severities throughout reflect the verifier's adjusted judgment, not the original finder's.
